# Guia legado arquivado — 2026-10-08

> Material histórico e não normativo. Pode conter comandos, números, caminhos, claims e práticas desatualizados. Use apenas como insumo; valide cada trecho contra o contrato ativo, o ambiente e fontes atuais.

Gera interfaces responsivas, componentizadas e com design system. Pergunta a stack, estrutura o projeto e entrega código limpo. Usa a skill `frontend-design` para criar designs distintivos e profissionais.

## Dependências

- **Design:** `sistema/identidade/design-guide.md` (para aplicar identidade visual)
- **Skill:** `frontend-design` (skill nativa do Claude Code para design)
- **Output:** `projetos/<nome>/src/components/` ou `frontend/`

## Workflow

### Passo 1 — Briefing

Perguntar ao usuário:

**1. Stack preferida:**
- React + Vite ou Next.js
- Vue + Vite ou Nuxt
- Svelte + SvelteKit
- Vanilla HTML/CSS/JS
- Outro (especificar)

**2. CSS/Estilização:**
- TailwindCSS
- Styled Components
- CSS Modules
- CSS puro
- Outro

**3. Library de componentes:**
```
┌─────────────────────────────────────────────────────────────┐
│                    QUAL LIBRARY USAR?                       │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  SHADCN/UI                                                  │
│  ├── Components pré-construídos em Radix UI                │
│  ├── Totalmente customizáveis                              │
│  ├── Copy-paste no projeto (não é npm install)            │
│  └── Melhor pra: dashboards, apps complexos               │
│                                                             │
│  BASE UI                                                    │
│  ├── Components leve e minimalista                         │
│  ├── API mais simples                                      │
│  ├── Bundle size menor                                     │
│  └── Melhor pra: landing pages, apps simples              │
│                                                             │
│  NENHUM ( vanilla )                                        │
│  ├── Components custom do zero                            │
│  ├── Controle total                                        │
│  └── Mais trabalho, mais liberdade                        │
│                                                             │
│  Qual prefere? (shadcn / baseui / nenhum)                  │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**4. Tipo de projeto:**
- Landing page
- Dashboard
- E-commerce
- App SaaS
- Outro

**5. Páginas/Telas necessárias:**
- Quais telas precisa?
- Principais funcionalidades?
- Integrações com API (sim/não)?

**6. Design:**
- Tem design em Figma/sketch?
- Quer que eu sugira o design?
- Seguir `sistema/identidade/design-guide.md`?

### Passo 2 — Design com frontend-design

Usar a skill `frontend-design` para gerar designs de alta qualidade:

1. Chamar a skill com o contexto do projeto
2. Aplicar identidade visual (`sistema/identidade/design-guide.md`)
3. Escolher library (shadcn/baseui/nenhum)
4. Gerar designs distintivos

### Passo 3 — Estrutura do Projeto

Criar estrutura baseada na stack e na library escolhida:

**React + TailwindCSS + Shadcn/UI:**
```
projetos/<nome>/
├── src/
│   ├── components/
│   │   ├── ui/          ← shadcn components (Button, Input, Card, etc)
│   │   │   ├── button.tsx
│   │   │   ├── card.tsx
│   │   │   ├── input.tsx
│   │   │   └── ...
│   │   ├── layout/      ← Header, Sidebar, Footer
│   │   └── features/    ← componentes específicos do projeto
│   ├── lib/
│   │   └── utils.ts     ← cn() helper do shadcn
│   ├── pages/
│   ├── hooks/
│   ├── services/
│   └── styles/
├── components.json      ← config shadcn
├── tailwind.config.js
├── package.json
└── vite.config.js
```

**React + TailwindCSS + Base UI:**
```
projetos/<nome>/
├── src/
│   ├── components/
│   │   ├── ui/          ← base ui components
│   │   ├── layout/
│   │   └── features/
│   ├── styles/
│   └── ...
├── package.json
└── tailwind.config.js
```

### Passo 4 — Setup da Library

**Shadcn/UI:**
```bash
# Inicializar
npx shadcn@latest init

# Adicionar componentes
npx shadcn@latest add button card input dialog sonner
```

**Base UI:**
```bash
npm install @base-ui/react
```

### Passo 5 — Componentes Base

Criar biblioteca de componentes base:

**Shadcn/UI Components:**
- Button (variants: default, destructive, outline, ghost)
- Input
- Card (Card, CardHeader, CardContent, CardFooter)
- Dialog
- Select
- Checkbox
- Toggle
- Badge
- Table
- Tabs

**Base UI Components:**
- Button
- Input
- Card
- Modal
- Select
- Checkbox
- Switch
- Badge
- Table

**Layout Components (ambos):**
- Container
- Grid/Flex layouts
- Header
- Sidebar
- Footer
- Page wrapper

### Passo 6 — Páginas

Implementar páginas com:
- Layout consistente
- Responsive design (mobile-first)
- Estados (loading, empty, error)
- Acessibilidade (ARIA labels, keyboard navigation)
- Performance (lazy loading, code splitting)

### Passo 7 — Integração

Se precisar de API:
- Services para chamadas
- Types para responses
- Error handling
- Loading states

- Border radius
- Sombras
- Iconografia

## Regras

- Perguntar a stack antes de começar
- **Perguntar sempre: shadcn, baseui ou nenhum?**
- Chamar skill `frontend-design` para designs distintivos
- Componentização: separar o máximo possível
- Responsivo: funcionar em mobile e desktop
- Acessibilidade: ARIA, keyboard navigation
- Performance: code splitting, lazy loading
- Código limpo: nomes descritivos, comentários quando necessário
- Aplicar design system consistentemente
- Props bem definidas com TypeScript types
- Estados: loading, error, empty, success
- Sempre criar componentes reutilizáveis
- Documentar componentes principais
