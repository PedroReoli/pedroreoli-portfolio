## Workflow

### Passo 1 — Análise da API

Perguntar ao usuário:
1. Qual a API que precisa documentar?
2. Qual a stack? (Express, FastAPI, NestJS, etc)
3. Tem endpoints definidos ou precisa mapear?
4. Quer documento completo ou específico?

### Passo 2 — Especificação OpenAPI

Gerar arquivo `openapi.yaml` com:

```yaml
openapi: 3.0.3
info:
  title: [Nome da API]
  description: [Descrição do que a API faz]
  version: 1.0.0
  contact:
    name: [Nome]
    email: [Email]
    url: [Website]

servers:
  - url: http://localhost:3000/api
    description: Development
  - url: https://api.exemplo.com
    description: Production

components:
  securitySchemes:
    bearerAuth:
      type: http
      scheme: bearer
      bearerFormat: JWT

  schemas:
    Error:
      type: object
      properties:
        message:
          type: string
        code:
          type: string
    User:
      type: object
      properties:
        id:
          type: string
        name:
          type: string
        email:
          type: string

paths:
  /users:
    get:
      summary: Listar usuários
      tags: [Users]
      security:
        - bearerAuth: []
      responses:
        '200':
          description: Lista de usuários
          content:
            application/json:
              schema:
                type: array
                items:
                  $ref: '#/components/schemas/User'
        '401':
          description: Não autenticado
```

### Passo 3 — Documentação por Endpoint

Para cada endpoint, documentar:

```
### [Método] /rota

**Descrição:** O que essa rota faz

**Autenticação:** Sim/Não

**Parâmetros:**
| Nome | Tipo | Obrigatório | Descrição |
|------|------|-------------|-----------|
| id   | string | Sim | ID do recurso |

**Body (se aplicável):**
```json
{
  "campo": "valor"
}
```

**Respostas:**
- `200` - Sucesso
- `400` - Erro de validação
- `401` - Não autenticado
- `403` - Sem permissão
- `500` - Erro interno

**Exemplo de resposta:**
```json
{
  "data": {}
}
```

**Exemplo de uso:**
```bash
curl -X GET "https://api.exemplo.com/recurso" \
  -H "Authorization: Bearer TOKEN"
```
```

### Passo 4 — README Completo

Gerar `README.md` com:

```markdown
# [Nome da API]

[Descrição breve]

## 🚀 Quick Start

### Pré-requisitos
- Node.js 18+
- PostgreSQL 14+

### Instalação
\`\`\`bash
npm install
cp .env.example .env
\`\`\`

### Variáveis de Ambiente
\`\`\`
DATABASE_URL=
JWT_SECRET=
PORT=3000
\`\`\`

### Rodar
\`\`\`bash
npm run dev
\`\`\`

## 📚 Endpoints

### Autenticação
| Método | Endpoint | Descrição |
|--------|----------|-----------|
| POST | /auth/register | Criar conta |
| POST | /auth/login | Login |
| POST | /auth/refresh | Renovar token |

### Usuários
| Método | Endpoint | Descrição |
|--------|----------|-----------|
| GET | /users | Listar usuários |
| POST | /users | Criar usuário |
| GET | /users/:id | Buscar usuário |
| PUT | /users/:id | Atualizar |
| DELETE | /users/:id | Deletar |

## 🔐 Autenticação

A API usa JWT. Para autenticar:

\`\`\`bash
curl -H "Authorization: Bearer SEU_TOKEN" \
  https://api.exemplo.com/protected
\`\`\`

## 🧪 Testes

\`\`\`bash
npm test
\`\`\`

## 📦 Deploy

[Instruções de deploy]

## 📄 Licença

MIT
```

## Regras

- Documentar TODOS os endpoints, sem exceção
- Exemplos completos e testáveis
- Manter documentação atualizada com código
- Seguir padrão OpenAPI 3.0
- Incluir erros possíveis em cada endpoint
- Documentar autenticação claramente
- Dar exemplos em múltiplas linguagens
- Versionar quando API mudar significativamente
