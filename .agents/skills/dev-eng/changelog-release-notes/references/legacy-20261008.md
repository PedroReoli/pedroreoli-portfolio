# Guia legado arquivado — 2026-10-08

> Material histórico e não normativo. Pode conter comandos, números, caminhos, claims e práticas desatualizados. Use apenas como insumo; valide cada trecho contra o contrato ativo, o ambiente e fontes atuais.

Transforme mudanças verificadas em changelog técnico e notas de versão para usuários. Confira diffs, artefatos e implantação antes de afirmar que uma função foi entregue.

---

## 🧭 Contexto do Negócio

Antes de gerar os documentos, solicite:
1. Os commits recentes (ou diffs das PRs).
2. O número da versão atual (Ex: `v1.4.2`).
3. Qual é o público-alvo principal desta release note? (Usuários finais B2C, clientes Enterprise B2B, ou apenas documentação interna do Github?).

---

## 📐 Parser de Conventional Commits

O modelo deve interpretar automaticamente os prefixos padrão do Conventional Commits e agrupá-los:
- `feat:` ➔ 🚀 **Novas Funcionalidades (Features)**
- `fix:` ➔ 🐛 **Correções de Bugs (Bug Fixes)**
- `perf:` ➔ ⚡ **Melhorias de Performance**
- `refactor:` ➔ ♻️ **Refatoração Interna**
- `docs:`, `chore:`, `test:` ➔ 🛠 **Tarefas de Manutenção (Ocultar ou agrupar no final)**

---

## 🧱 Templates de Saída

### 1. O Changelog Técnico (Formato GitHub Releases)

**v[Número da Versão] - [Data]**
*O que mudou:*
- 🚀 **Novidades**
  - Adicionado suporte a login via Google SSO (#123)
- 🐛 **Correções**
  - Resolvido crash na tela de pagamento no iOS 16 (#124)
- ⚡ **Performance**
  - Otimização na query de relatórios de vendas, reduzindo tempo em 40% (#125)

### 2. O Release Note para o Usuário Final (Amigável)

A linguagem técnica deve ser traduzida para benefícios de negócio.
*(Exemplo: Traduzir "fix: memory leak no redis" para "Melhoramos a estabilidade do sistema para você não enfrentar mais travamentos ao baixar planilhas").*

**O que há de novo na [Versão]? 🎉**

**Entre no sistema em um clique!**
Agora você pode fazer login usando sua conta do Google, sem precisar criar mais uma senha.

**Mais velocidade nos seus relatórios**
Nós arrumamos a casa internamente. Seus relatórios de vendas agora carregam quase na metade do tempo.

**Correções importantes:**
- O botão de pagar que sumia em alguns iPhones foi consertado.

---

## 📋 Regras de Tradução (Técnico ➔ Usuário)
- **Não mencione IDs de banco de dados ou arquivos.** (Nenhum usuário sabe o que é "Index db_user_x").
- **Foque no benefício.** Por que essa funcionalidade foi feita?
- **Seja transparente com bugs graves, mas positivo.** (Use "corrigimos uma instabilidade" ao invés de "sistema estava caindo e deletando dados").

---

## 📤 Formato de Saída (Output)

Sempre entregue:
1. **O Changelog Markdown (Para GitHub/GitLab).**
2. **O Texto de Release Note (Para o Blog / App Store / E-mail de Clientes).**
3. Caso identifique um breaking change (`BREAKING CHANGE:` ou `!`), destaque-o como prioridade máxima em ambas as visões com um alerta `> [!WARNING]`.
